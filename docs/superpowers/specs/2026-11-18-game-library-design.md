# Бібліотека ігор: гра зі списку замість вибору процесу

Дата: 2026-11-18. Статус: чернетка на погодження. Етап 1 з 4 напряму «Простий шлях для
звичайного гравця».

## Навіщо

Звичайний гравець не розуміє графіків і не знає, як називається exe його гри. Зараз, щоб
записати гру, треба вибрати процес зі списку запущених (`ProcessPicker`) або ввести ім'я exe
вручну. Для новачка це найнезручніше місце. Мета етапу — людина бачить **свої ігри з назвами
(і обкладинками, де вони є локально)**, натискає гру, запускає її як звичайно, а програма сама
знаходить процес гри.

Весь напрям (погоджено користувачем 2026-11-18, варіант «А, поетапно»):
1. **Бібліотека ігор** — цей документ.
2. Вердикт простими словами: програма сама складає з усіх метрик розповідь «як іде гра / чому
   були ривки / що зробити»; графіки — для експертного режиму.
3. Сценарій «Перевірити мою гру» на «Огляді»: вибір гри → гра 2–3 хв → вердикт → дія →
   «було / стало».
4. Перемикач «Простий / Експертний» на весь застосунок.

Етапи 2–4 мають окремі документи; тут лише те, що етап 1 мусить їм дати.

## Цілі / не-цілі / анти-цілі

- **Цілі:**
  - Список встановлених ігор із Steam, Epic, GOG і Battle.net: назва, лаунчер, тека, обкладинка
    (лише Steam, локально).
  - Вибір гри зі списку в «Діагностиці» (запис) і в «Іграх» (профіль режиму гри).
  - Процес гри визначається автоматично **за текою встановлення**; знайдений exe запам'ятовується.
  - Ручний вибір процесу лишається (гра без лаунчера, піратка, емулятор).
- **Не-цілі (етап 1):** кнопка на «Огляді» й сценарій (етап 3); запуск ігор із програми;
  обкладинки з мережі; іконки exe; Xbox / Game Pass, EA app, Ubisoft Connect, itch.io;
  розбір двійкового `appinfo.vdf` Steam.
- **Анти-цілі (провал, навіть якщо працює):**
  - Вгадувати exe (за розміром, за назвою) і записувати не ту програму без попередження.
  - Будь-який мережевий запит (обкладинки, назви, appid) — CLAUDE.md розд. 5.6.
  - Скан, що помітно навантажує систему або сканує диски цілком.
  - Падіння чи порожній екран, якщо маніфест лаунчера пошкоджений або диск бібліотеки відключено.

## Обмеження

- CLAUDE.md: системні виклики за трейтами (`RegistryApi`, `FsApi`…), парсери — чисті функції з
  тестами; без `unwrap`/`panic`; вердикти й логіка — лише в бекенді (10.8); типи для UI — ts-rs;
  i18n-ключі в `crates/core/locales/uk.json`; стиль — `docs/DESIGN.md`.
- **Не писати шляхи з пам'яті** (CLAUDE.md 14). Нижче — те, що звірено 2026-11-18 на реальному
  ПК користувача (Windows 11, Steam на `D:\Steam` + бібліотека `E:\SteamLibrary`, Epic, GOG,
  Battle.net). Що не звірено — позначено.
- Нова залежність — лише з дозволу. Цей етап нових залежностей не потребує (VDF — власний
  мінімальний парсер, JSON — `serde_json`, реєстр — `windows`).
- Програма може працювати від SYSTEM (служба) — шляхи `HKCU` і профілю користувача читаються
  для **інтерактивного** користувача, а не SYSTEM (див. «Де виконується»).

## Підходи (розглянуто)

| | Суть | Плюси | Мінуси |
|---|---|---|---|
| **1. За текою встановлення** | Бібліотека зберігає теку гри; при записі гра = процес, чий exe лежить у цій теці й малює кадри на передньому плані; exe запам'ятовується | однаково для всіх лаунчерів; сам обходить проміжні лаунчери (`PlayRDR2.exe` → `RDR2.exe`); без вгадування | треба шлях exe процесу; перший запис гри чекає, поки гра з'явиться |
| 2. Exe з маніфестів | Epic `MainWindowProcessName`, GOG `exe`, Battle.net `DisplayIcon`, Steam — `appinfo.vdf` або пошук exe в теці | exe відомий заздалегідь | Steam (найпопулярніший) — або недокументований двійковий формат, або вгадування; Epic — проміжні лаунчери |
| 3. Лише автовизначення запущеної гри | Без бібліотек: гра = процес на передньому плані, що малює | найпростіше | немає списку з назвами й обкладинками — не розв'язує проблему |

**Обрано 1** (користувач, 2026-11-18). Підказки exe з маніфестів (GOG `exe`, Epic
`MainWindowProcessName`, Battle.net `DisplayIcon`) використовуються лише як **попереднє
значення**, доки процес не підтверджено за текою (див. «Визначення процесу»).

## Дизайн

### 1. Джерела (звірено на реальному ПК 2026-11-18)

**Steam**
- Корінь: `HKCU\Software\Valve\Steam` → `SteamPath`; запасний `HKLM\SOFTWARE\WOW6432Node\Valve\Steam`
  → `InstallPath` (у користувача: `D:\Steam`).
- Бібліотеки: `<корінь>\steamapps\libraryfolders.vdf` — текстовий KeyValues: `"libraryfolders" {
  "0" { "path" "D:\\Steam" … "apps" { "<appid>" "<розмір>" … } } "1" { … } }`. Подвійні `\\` у
  рядках — екрановані.
- Гра: `<path>\steamapps\appmanifest_<appid>.acf` — `"AppState" { "appid" "name" "installdir"
  "StateFlags" … }`. Тека гри: `<path>\steamapps\common\<installdir>` (звірено). Гра без
  наявної теки не показується.
- `StateFlags`: на ПК користувача 12 ігор із `4` і одна з `6` (значення бітів не звірено з
  документацією). Не фільтрувати за `StateFlags` — критерій встановленості лише наявність теки.
- Обкладинка: `<корінь>\appcache\librarycache\<appid>\library_600x900.jpg` (звірено: є
  `header.jpg`, `library_600x900.jpg`, `library_hero.jpg`, `logo.png`). Нема файлу — без
  обкладинки. Інші формати каталогу кешу (старіші клієнти Steam) — не підтримуються в етапі 1.
- **Не-ігри.** `appmanifest` не каже, гра це чи інструмент. Відомий випадок на ПК користувача:
  appid `228980` (назва в `appmanifest` — «Steamworks Common Redistributables», звірено) — у
  короткому списку виключень лише звірені appid. Решта (напр.
  Wallpaper Engine) — людина ховає сама (п. 4).

**Epic Games**
- `%ProgramData%\Epic\EpicGamesLauncher\Data\Manifests\*.item` — JSON.
- Брати лише записи з `AppCategories`, що містить `"games"`, і `bIsIncompleteInstall == false`
  (звірено: рушії мають `engines`, плагіни — `plugins`).
- Поля: `DisplayName`, `InstallLocation`, `MainWindowProcessName` (може бути порожнім — звірено
  на Witch It), `LaunchExecutable` (часто проміжний лаунчер — **не** використовувати як exe гри).
- Дублікати (однаковий `InstallLocation` або `AppName`) зводити до одного запису.
- Обкладинка: лише URL (`VaultThumbnailUrl`) — **не використовується** (мережа).

**GOG**
- `HKLM\SOFTWARE\WOW6432Node\GOG.com\Games\<id>` → `gameName`, `path`, `exe` (повний шлях),
  `exeFile` (звірено на одній грі). Обкладинки немає (GOG Galaxy на ПК не встановлено; його
  база не підтримується в етапі 1).

**Battle.net**
- `HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*` (і 64-бітна гілка),
  `Publisher` містить `Blizzard` або `Activision` (звірено: «Call of Duty», `InstallLocation`
  `F:\Call of Duty`, `DisplayIcon` `F:\Call of Duty\_retail_\cod.exe`).
- Виключити сам лаунчер: запис, чий `DisplayIcon` веде на `Battle.net.exe` (звірено).
- `product.db` (protobuf) — не використовується.

### 2. Модель

Новий модуль у крейті `gamemode` (`library.rs`; він уже про «ігри й профілі» і не залежить від
UI). Типи з ts-rs:

```
GameEntry {
  id: String,            // стабільний: "steam:<appid>", "epic:<AppName>", "gog:<id>", "bnet:<ключ реєстру>"
  name: String,
  launcher: Launcher,    // Steam | Epic | Gog | Battlenet | Manual
  install_dir: String,
  exe: Option<String>,   // підтверджене ім'я exe (з визначення процесу) — пріоритет
  exe_hint: Option<String>, // з маніфесту, ще не підтверджене
  has_cover: bool,
  hidden: bool,
}
LibraryReport { games: Vec<GameEntry>, problems: Vec<LibraryProblem> } // проблема: лаунчер/файл + причина
```

- Парсери: `parse_libraryfolders(&str)`, `parse_appmanifest(&str)`, `parse_epic_item(&str)` —
  чисті функції; GOG / Battle.net — функції над значеннями реєстру, отриманими через `RegistryApi`.
- Збірка списку: `scan_library(fs, reg) -> LibraryReport` поверх трейтів, тестується моками.
- Стан користувача (`library.json` у теці даних): `id → { exe підтверджений, hidden }` +
  вручну додані ігри. Скан не перезаписує ці поля.
- Пошкоджений файл / відсутній диск бібліотеки → запис у `problems` і в журнал, решта списку
  показується. Нічого не падає.

### 3. Визначення процесу гри

- `ProcessInfo` отримує поле `path: Option<String>` (повний шлях exe; `None`, якщо Windows не
  дала — захищений процес).
- Чиста функція `match_game(install_dir, processes) -> Option<ProcessInfo>`: процес, чий шлях
  **канонізовано** лежить усередині `install_dir` (порівняння без урахування регістру, з
  роздільником на кінці, щоб `F:\Games\Foo` не збігалось із `F:\Games\FooBar`).
- Запис гри з бібліотеки:
  - є підтверджений `exe` → як зараз (запис за ім'ям exe, `StartMode::Auto`);
  - немає → новий варіант очікування в шлюзі запису: «чекаємо процес з теки гри на передньому
    плані, що малює кадри». Кілька кандидатів (лаунчер + гра) — береться той, що на передньому
    плані й малює (PresentMon). Знайдений exe зберігається в `library.json` і показується в UI
    («Гру визначено: RDR2.exe»).
  - `exe_hint` лише показується як «очікуємо: X» і не підміняє перевірку за текою.
- Профіль режиму гри для гри з бібліотеки створюється, коли exe підтверджено; до того — кнопка
  «Запусти гру один раз, щоб програма її впізнала» (профілі лишаються за ім'ям exe, формат
  `GameProfile` не змінюється).

### 4. UI

- Новий компонент `GamePicker` (замінює `ProcessPicker` у «Діагностиці» й «Іграх», сам
  `ProcessPicker` лишається всередині як вкладка «Запущені процеси / Вручну»):
  - сітка карток: обкладинка (або перша літера назви на плитці), назва, бейдж лаунчера
    (текст + іконка), «exe визначено / ще не визначено»;
  - пошук за назвою; «Приховати» на картці; «Показати приховані»; «Оновити список»;
  - стани: завантаження / порожньо («Лаунчерів не знайдено — вибери процес вручну») / помилка /
    частково (є `problems` — тихий рядок «Не вдалося прочитати: Epic (файл пошкоджено)»).
- Обкладинки: бекенд віддає байти файлу за `id` гри (команда, що сама будує шлях із кореня
  Steam і appid, — **фронтенд шлях не передає**). Без asset-протоколу з широким доступом до диска.
- Токени й компоненти — `docs/DESIGN.md`; макет картки — на розсуд builder у межах дизайн-системи.

### 5. Де виконується

- Скан бібліотеки — у процесі програми (інтерактивний користувач: його `HKCU`, його профіль),
  а не в службі SYSTEM. Читання `HKLM` і `ProgramData` працює без прав адміністратора.
- Визначення процесу за текою — там, де зараз шлюз запису (служба або програма). Builder
  перевіряє, що шлях exe процесу доступний у обох режимах.
- Скан запускається при першому відкритті вибору гри в сесії і кнопкою «Оновити»; результат
  кешується в пам'яті. Читаються лише конкретні файли й ключі — жодного обходу дисків.

### 6. Тести

- Парсер VDF: зразки у форматі, звіреному на ПК (дві бібліотеки, екрановані `\\`, порожні
  рядки, коментарі `//`, пошкоджений файл → помилка, а не паніка).
- `appmanifest`, Epic `.item` (гра / рушій / плагін / незавершене встановлення / дублікат),
  GOG і Battle.net через мок `RegistryApi` (виключення самого Battle.net).
- `match_game`: вкладена тека, схожий префікс (`Foo` vs `FooBar`), регістр, `..`, змішані
  роздільники, процес без шляху, кілька кандидатів.
- `scan_library` на моках: відсутній диск, відсутня тека гри, порожні лаунчери, стан
  користувача (hidden / exe) не перезаписується.
- Зразки — знеособлені (без `LastOwner`, SteamID, імен користувача).

## Що лишається builder

- Точна форма команд Tauri і подій; розміщення `GamePicker` у шапці «Діагностики».
- Як саме шлюз отримує шлях процесу (`sysinfo` уже є в залежностях або
  `QueryFullProcessImageNameW` за трейтом) — з перевіркою на реальному Windows в обох режимах
  (служба / без служби).
- Макет картки в межах `docs/DESIGN.md`.

## Рішення, ухвалені асистентом (перевір)

1. Модуль — у крейті `gamemode`, а не новий крейт.
2. Програма **не запускає** ігри (без `steam://`): людина запускає як звичайно.
3. Обкладинки лише Steam; для решти — перша літера назви (іконки exe — пізніше).
4. Не-ігри Steam: лише звірені appid у виключеннях + «Приховати» вручну.
5. Підказка exe з маніфестів не використовується без підтвердження за текою.
6. Власний мінімальний парсер VDF замість нової залежності.

## Перевірка користувачем (після реалізації)

- Список містить ігри Steam з D:, E: і F:, Kerbal Space Program (GOG); немає Unreal Engine,
  плагінів, Battle.net-лаунчера, Steamworks Common Redistributables.
- Виправлено після реалізації: Epic (RDR2, Witch It, Genshin) і Battle.net (Call of Duty) на ПК
  користувача видалені — маніфести й записи реєстру лишились, тек немає, тож у списку їх **не
  має** бути (усі лаунчери показують гру лише з наявною текою).
- Запис гри з бібліотеки, у якої ще немає exe, визначає саму гру, а не її лаунчер.
- Відключений диск бібліотеки не ламає список.
