# «Перевірити мою гру» з «було / стало» — дизайн

Дата: 2026-11-19. Етап 3 «простого шляху для звичайного гравця» (етапи 1 — бібліотека ігор і 2 —
вердикт простими словами — готові; етап 4 — перемикач «Простий / Експертний»).

## Навіщо

Новачок не знає, що вкладка «Діагностика» → «Чому лагає?» → налаштування запису → «Почати» — це і є
перевірка гри, і не знає, що після поради треба записати ще раз, щоб побачити, чи вона допомогла.
Етап 3 дає один шлях від «Огляду» до відповіді: **вибрав гру → грав 2 хв → розповідь → одна дія →
«було / стало»** з чесним висновком.

## Цілі

- На «Огляді» — картка «Перевірити мою гру» з кнопкою; під нею — підсумок останньої перевірки.
- Сценарій веде «Діагностика» (рішення користувача: «Огляд» запускає, «Діагностика» веде) зі
  смужкою з п'яти кроків: Гра · Запис · Вердикт · Дія · Було / стало.
- «Було / стало» — повторний запис тієї самої гри з тією самою тривалістю й сценою, порівняння саме
  із записом «було» (а не з «якимось попереднім»).
- Висновок залежить від дії (рішення користувача: «б»): дія проти ривків — за 1% low, решта — за
  середнім FPS; поріг той самий, що в «Історії» (похибка обох записів, не менше 8 %).
- Один запис нічого не довів (в межах похибки) і дію можна перемкнути в грі — пропозиція
  «Перевірити точно (A/B)» з готовими варіантами (рішення користувача: «В»).

## Не цілі

- Перемикач «Простий / Експертний» — етап 4.
- Майстер цілком на «Огляді» (відхилено користувачем: логіку запису довелося б дублювати).
- Нові вимірювання, нові пороги, зміна правил діагностики чи наявного `history::compare`
  (висновок «Історії» й попереджень «FPS впав» лишається за середнім FPS).
- Відновлення незавершеного сценарію після перезапуску програми (стан сценарію — лише в сесії;
  записи, звісно, лишаються в «Історії»).
- Автоматичне застосування дії: людина робить її сама (в грі чи кнопкою знахідки, як зараз).

## Антицілі (провал, навіть якщо «працює»)

- «Стало краще», коли різниця менша за поріг, або обіцянка приросту до вимірювання.
- Порівняння з іншим записом, ніж «було» (інша гра, запис з «Історії» між ними).
- Мовчки інша сцена чи інша тривалість у «стало»: якщо умови різняться — попередження, як в «Історії».
- Логіка висновку у фронтенді (CLAUDE.md 10.8).
- Дубль на екрані: «було / стало» і поруч «Проти попереднього запису» з тими самими числами.

## Підходи

Як міряти «було / стало» (обрано: В):
- А. Лише повторний запис — швидко, але один запис проти одного (±5–10 %) і нічого далі.
- Б. Лише A/B 3 + 3 — точно, але шість прогонів і лише для дій, що перемикаються в грі.
- **В. Повторний запис, а при «в межах похибки» — пропозиція A/B** (обрано).

Де живе сценарій (обрано: 1):
- **1. «Огляд» запускає, «Діагностика» веде** (обрано): запис, визначення гри, помилки, генерація
  кадрів — наявний код без копій.
- 2. Майстер на «Огляді» — винести або продублювати ≈ 450 рядків станів запису.

Що вважати «краще» (обрано: б):
- а. Лише середній FPS, ривки — опис без висновку.
- **б. Метрика висновку — за дією** (обрано).

## Як це працює

### Бекенд

**Метрика висновку** (`crates/diagnosis`, чиста функція з тестами):
`check_focus(&Diagnosis) -> Option<CheckFocus>`, `CheckFocus = Fps | Lows`. Береться знахідка
головної дії розповіді (`story.action`): категорія `Stutter`, `Background` або `Vram` → `Lows`
(це про ривки), будь-яка інша → `Fps`. Немає розповіді чи дії (`Fine`, `Insufficient`) → `None`
(перевіряти нічого).

**Зв'язок «було → стало» в історії** (`crates/history`): нове поле
`HistoryEntry.check: Option<CheckLink { baseline: String, focus: CheckFocus }>`
(`#[serde(default)]`, старі записи читаються). Записується, коли запис зроблено як перевірку:
`diag_start` отримує необов'язковий `check_of: Option<String>` (id запису «було»); бекенд сам
обчислює `focus` з діагнозу «було» (останній результат, якщо його id збігається, інакше — з
«Історії»). Невідомий id чи `None`-фокус → помилка команди, запис не стартує.

**Висновок** (`crates/history`, чиста функція з тестами):
`check(baseline, after, focus) -> CheckComparison { cmp: RecordComparison, focus, trend: Trend }`.
`cmp` — наявний `compare`, без змін. `trend` — за `avg_fps` (`Fps`) або `low_1pct_fps` (`Lows`)
з тим самим `threshold_pct`. Немає метрики в одному з записів → `Unknown`.

**Команди** (`crates/app`):
- `check_result(id) -> Option<CheckResult>` — для запису-перевірки: `CheckComparison` + `ab:
  Option<[Text; 2]>` (варіанти з `Finding.next = Compare` головної дії «було», лише коли `trend` —
  `Same` чи `Unknown`). Не перевірка → `None`.
- `check_last() -> Option<CheckResult>` — найновіший запис-перевірка (для картки «Огляду»).

### Інтерфейс

**«Огляд»** — нова картка над «Станом ПК»:

```
┌ Перевірити мою гру ─────────────────────────────────────┐
│ Вибери гру, пограй 2 хвилини — програма скаже, що        │
│ заважає і чи допомогла зміна.                  [Почати]  │
│ Остання перевірка: Cyberpunk 2077 · 72 → 81 FPS · краще  │
└──────────────────────────────────────────────────────────┘
```

«Почати» → `ui.screen = "diagnosis"`, вкладка «Чому лагає?», режим сценарію (стан у
`ui` — сесія), тривалість 120 с, налаштування запису розгорнуто з вибором гри.

**«Діагностика» в режимі сценарію** — над вмістом смужка кроків (текст + номер, поточний виділено,
не лише кольором):

```
① Гра ✓ ─ ② Запис ✓ ─ ③ Вердикт ✓ ─ ④ Дія ─ ⑤ Було / стало
```

- ①–② — як зараз (вибір гри, визначення процесу, хід запису).
- ③ — розповідь етапу 2. `Fine` → сценарій завершено («Усе гаразд: виправляти нічого»), кроки ④–⑤
  неактивні. `Insufficient` → кнопка «Записати ще раз».
- ④ — під розповіддю блок «Зроби це й перевір»: головна дія (та сама порада), підказка «Грай ту
  саму сцену, що й зараз» і кнопка **«Я зробив — записати ще раз»** (та сама гра, тривалість, сцена
  «було»; `check_of` = id запису «було»). Якщо людина зробила інший варіант з «Інших варіантів» —
  висновок однаково за метрикою головної дії (обмеження, в тексті не пояснюємо).
- ⑤ — на результаті запису-перевірки картка «Було / стало» замість «Проти попереднього запису»:
  наявний `ComparisonSummary` + рядок висновку за метрикою фокусу:
  - краще → «Допомогло: 1% low 48 → 61 (+27 %, поріг 9 %). Залиш так.»
  - гірше → «Стало гірше … Поверни як було.»
  - в межах похибки → «Різниці не видно: один запис проти одного.» + кнопка «Перевірити точно
    (A/B)», якщо `ab` є (відкриває «Порівняння» з варіантами, як `openCompare`).
  Під нею — нова розповідь «стало» (звичайний результат).
- Вихід зі сценарію: «Завершити перевірку» (смужка зникає) або інша вкладка/гра.

Запис-перевірка, відкритий з «Історії», теж показує «Було / стало» (`check_result` за id).

Тексти — `ui.check.*` у `uk.json`; висновок — з `ui.check.trend.{better|worse|same|unknown}.{fps|lows}`.

## Перевірка

- Rust: `check_focus` (кожна категорія, `Fine`/`Insufficient` → `None`); `check` (обидві метрики,
  межа порога, немає 1% low → `Unknown`, порядок аргументів); `HistoryEntry` без `check` читається;
  `diag_start` з невідомим `check_of` — помилка.
- e2e (мок): картка «Огляду» → «Діагностика» зі смужкою; «Я зробив» передає `check_of`, гру,
  тривалість і сцену; «Було / стало» для кожного висновку; A/B лише при «в межах похибки» з
  `ab`; `Fine` завершує сценарій; без сценарію «Діагностика» як зараз.
- Реальний Windows — чекліст: пройти сценарій у грі з DLSS вимк./увімк. (Fps) і з фоновим
  процесом закрито/відкрито (Lows); перезапуск гри між записами (визначення exe знову).

## Рішення автора спеки (не обговорювались — перевір)

- Категорії «про ривки» для `Lows`: `Stutter`, `Background`, `Vram`. `Unexplained` (дія —
  `stutter.unknown`) теж `Lows`.
- Запис «було» без сирого запису в «Історії» (діагноз не відновити) → «Я зробив» не стартує, текст
  «Запис «було» недоступний — почни перевірку заново».
- «Стало» записується з тим самим exe (уже визначеним — без повторного очікування гри) і тією
  самою тривалістю, що «було»; людина може змінити їх, тоді `ComparisonSummary` уже попереджає
  про різні умови (сцена) — тривалість у попередження не додаємо.
- Ланцюжок: після «стало» можна знову «Я зробив — записати ще раз»; «було» лишається першим
  записом сценарію (порівнюємо з вихідним станом, а не з проміжним).

## Лишено будівельнику

- Розмітка смужки кроків і картки «Огляду» в межах токенів (`docs/DESIGN.md`).
- Звідки взяти діагноз «було» для `focus`, якщо програму не перезапускали (стан `diag_state`) і
  якщо перезапускали (`history_open`).
- Чи вибирати на «Огляді» гру одразу (попередньо — остання записана гра з бібліотеки) — на розсуд,
  головне: один клік до вибору гри.

## Доповнення 2026-11-20: необов'язкова дія «Спробувати»

**Навіщо.** Користувач пройшов сценарій на грі з межею відеокарти (80 FPS на моніторі 200 Гц):
розповідь казала «Нічого робити не треба», поруч — згорнуті «Інші варіанти (2)», а сценарій
закінчувався сірою плашкою «Усе гаразд: перевіряти нічого». Його слова: «виглядають дуже тупо і
пусто… я пройшов етап вердикт, і далі що?». «Усе гаразд» означає «нічого не зламано», а не «далі
нічого» (рішення користувача: варіант А).

**Що змінюється:**
- `Fine` з порадами в `others`: замість «Нічого робити не треба» і згортки — одразу список
  «Хочеш ще краще? Спробуй (необов'язково):» з тими самими порадами й кнопками наступного кроку
  (A/B, апскейл). З головною дією — як було (дія + згортка «Інші варіанти»).
- У сценарії біля кожної поради (головної й інших) — «Спробувати»: крок ④ «Зроби це й перевір»
  з обраною порадою й «Я зробив — записати ще раз», далі ⑤. Без вибору — головна дія (як було).
- План перевірки — для обраної знахідки: `check_plan(d, finding: Option<&str>)` (id знахідки, бо
  запис «було», заново проаналізований з «Історії», може мати інший порядок); знахідка мусить
  бути головною дією чи серед `others`. `Fine` з вибраною знахідкою — дозволено; `Insufficient` —
  ні. `CheckPlan.advice` — текст поради; у «Було / стало» рядок «Що змінено: …» (і в «Історії»).
- `Fine` без жодної поради: замість плашки — завершальна картка (галочка, «Перевірку завершено»,
  «Несправностей немає, і порад для цієї гри теж немає. Перевір ще раз після оновлення драйвера чи
  гри.», кнопки «Завершити» і «Перевірити іншу гру»).

**Не цілі:** еталони й нагадування (варіант В), нові поради чи пороги.

**Рішення автора:** заголовок списку нейтральний — «Хочеш ще краще?» (а не «більше кадрів»):
поради `Fine` бувають і про ривки.
