# «Що робити далі» — план реалізації

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** під порадами результату діагностики — кнопки наступного кроку (A/B, апскейл), автоматичне
порівняння з попереднім записом гри, результат без дублювання з експертними розборами в одній
згортці, чесні бейдж «До відома» й кільце «Головної».

**Architecture:** бекенд вирішує все: крок знахідки (`Finding.next`, `diagnosis`), вибір
попереднього запису (`history::previous_of` + команда `history_vs_previous`), області аудиту
(`AuditReport.areas`). Фронтенд лише малює й переходить між вкладками через наявний пресет
«Порівняння».

**Tech Stack:** Rust (core, diagnosis, history, audit, app/Tauri 2), ts-rs, Svelte 5 + TS strict,
Playwright.

**Spec:** `docs/superpowers/specs/2026-11-16-next-step-design.md`

## Global Constraints

- Бізнес-логіка (який крок, який попередній запис, підрахунок областей) — лише в Rust (CLAUDE.md 10.8).
- Нові поля в серіалізованих типах — `#[serde(default)]`: старі записи історії читаються.
- Без `unwrap()/expect()/panic!` у продакшн-коді; `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`.
- Рядки UI — лише в `crates/core/locales/uk.json`; `npm run check`, `npm run check:i18n`, `npm run check:e2e`.
- TS-типи перегенерувати: `cargo test -p optimax-app export_typescript_bindings`.
- Порівняння «один запис проти одного» ніколи не подається як доведений ефект: на картці завжди «Один запис проти одного; доказ — A/B».
- Кольори — лише токени; бейдж — текст + крапка, як інші (CLAUDE.md 10.3).
- **Git не чіпати** (користувач коммітить сам): замість кроку «Commit» — прогнати перевірки.

## Review Focus

1. Старий запис історії (JSON без `next`) відкривається в «Історії» без помилки — тест у Task 1 (serde) і Task 3 (`history_open` не ламається: покрито serde-тестом `Finding`).
2. Перший запис гри — картки «Проти попереднього» немає, без помилки й без порожньої плитки — тест у Task 3 (`None`) і Task 7 (e2e без картки).
3. Запис іншої гри між двома записами — порівнюється з попереднім записом **тієї ж** гри, назва гри без урахування регістру (`RE9.exe` = `re9.exe`) — тест у Task 3.
4. Подія `history-saved` приходить після того, як користувач уже почав новий запис — картка не прив'язується до чужого результату: `ui.lastRecordId` скидається на `diag-done` — e2e у Task 7.
5. Кнопка A/B з «Історії» (відкритий старий запис) — переходить у вкладку «Порівняння» з грою того запису — e2e у Task 6.
